Case Study

SECOM Manufacturing Defect Prediction

Industrial sensor data · Imbalanced binary classification · Python / Scikit-learn

The problem

On a semiconductor manufacturing line, hundreds of sensors record process conditions for every unit that comes off the line. Only a small fraction of units actually turn out defective — in this dataset, just 6.6%. That imbalance is the real challenge: a model that simply predicts "pass" for everything would already be right 93% of the time, while catching zero real defects. The goal wasn't raw accuracy — it was building a model that actually catches failing units before they leave the line.

The data

The SECOM dataset contains 1,567 production records, each described by 590 anonymized sensor and process-measurement features, with a binary pass/fail label. Like most real sensor data, it came with its own problems: missing readings, features with almost no variance, and clusters of sensors highly correlated with each other — all of which needed to be handled before any model could learn something meaningful.

Pipeline

  • Cleaning & feature filteringImputed missing sensor readings, dropped near-constant features, and reduced redundancy among highly correlated sensors.
  • Exploratory data analysisExamined sensor distributions and correlation clusters to separate signal from noise.
  • Stratified train/test splitPreserved the 6.6% failure ratio in both sets so evaluation reflected the real class balance.
  • Imbalance handling with SMOTEApplied SMOTE oversampling on the training data only, to avoid leaking synthetic samples into evaluation.
  • Model comparisonTrained and compared Logistic Regression (baseline), Random Forest, and SVM.
  • Imbalance-aware evaluationScored every model on Precision, Recall, F1 and ROC-AUC rather than accuracy, since recall on the defect class was what actually mattered.
  • Threshold tuningAdjusted the decision threshold after training to push defect-detection recall higher, at a deliberate, measured cost to precision.

Recall on the failure class improved substantially over the untuned baseline — meaning far fewer defective units would slip through undetected, which is the metric that actually matters on a production line.

Case Study

YouTube Trending Videos — Regression Analysis

Kaggle dataset · Regression modeling · Python

The problem

Trending videos on YouTube aren't random — engagement metrics like views, likes and comments follow patterns tied to category, timing and channel behavior. The goal was to model those patterns: given a video's metadata and engagement signals, estimate how it performs, and compare how different regression algorithms handle the messiness of real platform data.

The data

The dataset comes from Kaggle's YouTube Trending Videos collection, combining video metadata — title, category, channel, publish time — with engagement metrics such as views, likes and comments. Like most scraped platform data, it needed real cleanup before modeling: duplicate entries, inconsistent date formats, and categorical fields that needed proper encoding.

Pipeline

  • Exploratory data analysisStudied how views, likes and comments were distributed across categories, and how strongly engagement metrics correlated with each other.
  • CleaningRemoved duplicate records, handled missing fields, and standardized publish-date formats.
  • PreprocessingEncoded categorical fields (category, publish weekday/hour) and scaled numeric features for the distance-based models.
  • VisualizationBuilt category-level trend charts and correlation heatmaps to guide feature choices before modeling.
  • Baseline modelingStarted with Linear Regression as a simple, interpretable baseline.
  • Model comparisonTrained and compared Random Forest, XGBoost, LightGBM, CatBoost, SVR, KNN Regressor and Extra Trees Regressor against the baseline.

What stood out

The gradient-boosting models — XGBoost, LightGBM, CatBoost — handled the nonlinear relationships in engagement data more consistently than the Linear Regression baseline, which struggled once category and timing effects stopped behaving linearly. A good reminder that the "obvious" first model is a baseline to beat, not the answer.
